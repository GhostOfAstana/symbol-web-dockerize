# Выполненные проверки

Дата подготовки: 25 октября 2026 года. Среда: Linux amd64, установленный Go 1.26.8. Дополнительные программы на пользовательский компьютер не устанавливались.

## Подтверждено при подготовке

- `go test -race -cover ./...` — все пакеты прошли. Проверены генератор, HTTP, CLI, монитор и базовый текстовый помощник.
- `go vet ./...`, отсутствие вывода `gofmt -l .`, `bash -n scripts/docker-smoke.sh`, `node --check` для обоих JS-файлов — без ошибок.
- Собственный Dockerfile проходит четыре из четырёх проверок `health-monitor --lint`.
- `FuzzScore`, 10 секунд, четыре worker: 929 258 запусков, без ошибки.
- `FuzzDockerJSON`, около 10 секунд: 381 230 запусков, без ошибки.
- `FuzzGenerate`, 5 секунд: 605 925 запусков, без ошибки.
- Собранный HTTP-сервер обслужил главную страницу, healthcheck, CSS, оба JS-файла, все три шрифта и три JSON endpoint текстового помощника.
- Без настройки HTTP-монитор вернул ожидаемый 503, а `/healthz` — 200.
- Нагрузка: 200 запросов с крупным `shadow`-баннером, 32 клиента. Получены 174 успешных ответа и 26 ответов 503 из предусмотренного ограничителя. После нагрузки `/healthz` остался доступен с 200. Случай распределения зависит от мощности хоста; 503 при занятых восьми слотах — ожидаемая реакция с повтором через секунду.
- Docker Registry подтвердил существование обоих базовых тегов; их manifest digest зафиксирован в Dockerfile.

Покрытие инструкций по пакетам: `internal/ascii` — 93,6%, `internal/handlers` — около 90%, `internal/monitor` — 86,4%, `internal/textai` — 90,7%, CLI — 61,4%. `cmd/server` проверялся запуском отдельного собранного процесса; собственных unit-тестов orchestration main у него нет.

## Проверка настоящего Docker

Использован уже установленный Docker Desktop, Engine 29.4.2; новое ПО на компьютер не устанавливалось. Образ собран из проектного Dockerfile с закреплёнными digest базовых образов. Docker сообщил `Size = 9967648` байт для проверенной первой сборки.

Подтверждено на реальном контейнере:

- Запуск с UID/GID 10001, Bash и всеми ожидаемыми файлами `/app`. Проверены метки образа и контейнера.
- Файловая система только для чтения, `cap-drop ALL`, `no-new-privileges`, 128 МиБ памяти, один CPU и предел 64 процессов.
- Docker HEALTHCHECK перешёл в `healthy`; `OOMKilled=false`.
- Все HTTP-маршруты, три шрифта и три endpoint текстового помощника работают. Для `hello`/`standard` реально получены 256 байт, восемь строк шириной 31.
- Ошибки 400/404/405/413 и отключённый контейнерный HTTP-монитор с 503 проверены настоящими запросами.
- Нагрузка внутри контейнера: 200 крупных запросов, 32 клиента; 189 ответов 200 и 11 ответов 503 с `Retry-After: 1`. Затем `/healthz` вернул 200; контейнер остался запущенным и не был убит по памяти.
- Host CLI `health-monitor` действительно вызвал Docker inspect/stats: uptime 19,5155 с, память 3,23%, CPU 0%, перезапуски 0. Баллы `0 + 25 + 25 + 25 = 75`, рейтинг `3 stars (Fair)`. Это ожидаемая оценка нового контейнера; время работы не подменялось для получения 100.
- Host HTTP-монитор затем прочитал uptime 66,1918 с, память 7,17%, CPU 2,48%, перезапуски 0: `5 + 25 + 25 + 25 = 80`, `4 stars (Good)`. При восьми одновременных обращениях один получил 200, остальные семь — 503 с `Retry-After: 2`.
- SIGTERM через `docker stop` завершил приложение с `ExitCode=0`, без OOM. Остановленный и отсутствующий контейнер дают ненулевой код CLI. Host endpoint после остановки вернул 503, а его собственный `/healthz` сохранил 200.
- Тестовый контейнер удалён после проверки. Сборочный образ и временный builder удаляются при общей завершающей очистке.

Для повторения подготовлены `scripts/docker-smoke.sh` и отдельное задание `container` в GitHub Actions. Удалённый CI считается пройденным только после завершения конкретного запуска; описанная проверка выше была отдельным реальным запуском Docker Desktop. Примеры 100 и 30 баллов в unit-тестах отдельно проверяют таблицу на управляемых данных.
